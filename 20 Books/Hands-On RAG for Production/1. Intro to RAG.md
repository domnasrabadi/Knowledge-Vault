- RAGs 2 steps (naive/simplest view)
	- retrieval
		- retrieve information related to the query via a search algorithm (multiple options)
	- generation
		- "*augmented*" = retrieved info is added to the prompt of the LLM to generate the response 

![[Screenshot 2025-12-29 at 2.24.05 pm.png| center | 400]]

- RAG stack blue print
	1. (offline) embed & index documents
	2. (offline) store doc embeddings in vector store
	3. (online) query gets sent
	4. (online) query is embedded & compared against vector store embeddings
		1. (online) or using keyword search algorithm on actual document text (BM25)
		2. (online) or using hybrid search combining embedding + keyword search
	5. (online) top $n$ documents/chunks retrieved that are relevant to the query
	6. (online) reranking
- benefits of RAG
	- <span style="color:rgb(0, 176, 80)">scalable & efficient</span> → can scale to hundreds/thousands of docs, can instantly remove & add docs
	- <span style="color:rgb(0, 176, 80)">helps reduce hallucinations</span> → since it provides evidence content to ground response in 
	- <span style="color:rgb(0, 176, 80)">improves explainability & control</span> → can have citations, can control what docs get used/not used
- key use-cases
	- virtual assistants + QA chatbots
	- enterprise knowledge mgmt + internal search
	- automated content creation
	- document summarisation 
	- research
- advanced RAG use-cases
	- <mark style="background: #ADCCFFA6;">agentic RAG</mark>
		- instead of one-shot search, incorporates additional agents
			- iterative + multi-step retrieval → agents can re-retrieve & refine info
			- tool use → can access various sources e.g. web, rather than pre-ingested docs
			- advanced reasoning + adaptability → can decompose complex queries, plan retrieval strategy + validate info 
		- overall more flexible + robust, esp. for complex + multi-faceted queries
			- via dynamically orchestrating multiple retrieval + reasoning steps 
	- <mark style="background: #ADCCFFA6;">multi-modal RAG</mark>
		- includes being able to interpret tables, diagrams, charts, images
		- 2 methods to do this
			- convert all modalities into text (e.g. images to captions) then run normal RAG
			- leverage multimodal retrieval + embedding models
	- <mark style="background: #ADCCFFA6;">graphRAG</mark>
		- improves retrieval quality by using knowledge graphs
		- processes documents, extracts entities + relationships, build a knowledge graph capturing connections within data
			- output = structured representation of connected info 
			- allowing for multi-hop reasoning + deeper context + awareness
		- benefits = connects info that isn't reachable from a single piece of info
