# 1 Inference Challenges
- decoder transformers are autoregressive, imposing sequential limitation
- self-attention operation is quadratic in nature
	- as sequence length increase, compute required increases quadratically $s^2$
# 2 Inference Optimisation Techniques 
- efficient inference should satisfy 3 goals 
	- reducing compute
	- speeding up decoding 
	- reducing storage needs 
## 2.1 Reducing Compute
### 2.1.1 Caching 
- <mark style="background: #FFB8EBA6;">caching</mark> = trades compute for extra storage
	- <mark style="background: #FFB8EBA6;">K-V Caching</mark> = solves how when previous conversations added to inputs, causing lots of repetition in computations 
	- can cache the data + re-use when required
- process
	- cache the $K$ and $V$ (keys and values) of self-attention blocks - known as KV Cache
	- instead of unnecessary overhead of repetitively processing instruction tokens
	- consults cache to fetch KV values for those tokens
- especially useful in settings with many repeated instructions for large number of calls
	- or context window contains data e.g. documentation that persists across calls 
### 2.1.2 Knowledge Distillation
- <mark style="background: #FFB8EBA6;">knowledge distillation</mark> = deriving smaller model from larger model with preserved capabilities 
	- e.g. DistilBERT - smaller models that approximate capabilities of larger models, enabling faster inference
		- base model = **teacher model**, distilled model = **student model**
- 2 steps to distillation = preparing distillation data then training
	- preparing distillation data can be done multiple ways 
		- <span style="color:rgb(255, 0, 247)">Unsupervised generation</span> = prompt teacher with instructions or examples to create distillation data 
			- including reasoning for chain of thought, asking teacher to explain thought process leading to answer
		- <span style="color:rgb(255, 0, 247)">Data augmentation</span> = teacher given seed input output examples then generates similar pairs but may lack diversity
		- <span style="color:rgb(255, 0, 247)">Intermediate representations</span> = white box distillation using teacher intermediate representations
			- to align student via KL-divergence on activations or logits 
		- <span style="color:rgb(255, 0, 247)">Teacher feedback</span> = teacher assesses outputs of student model
			- and provides feedback in form - e.g. preference data or detailed feedback to improve(RLAIF)
		- <span style="color:rgb(255, 0, 247)">Self-teaching</span> = student refines its own outputs by generating $n$ responses with reasoning and choosing best one  
	- techniques to perform distillation 
		- <span style="color:rgb(255, 0, 247)">Supervised fine-tuning</span> = student fine-tuned on distillation set to mimic teacher outputs
		- <span style="color:rgb(255, 0, 247)">KL Divergence of output probabilities</span> = minimise divergence between teacher and student output probability distributions
		- <span style="color:rgb(255, 0, 247)">Internal representation similarity</span> = instead of minimising divergence, maximise similarity between them
			- align teacher and student internal representations layerwise (white box)
		- <span style="color:rgb(255, 0, 247)">Reinforcement learning</span> = train reward model on distillation data and optimise student to maximise reward
- studies show you don't need massive dataset to do well
	- around 1k high quality examples can be enough e.g. LIMA paper 
- for actual training, without access to teacher weights - can only do SFT 
### 2.1.3 Early Exit (Dynamic Inference)
- <mark style="background: #FFB8EBA6;">early exit</mark> = foregoing certain operations during inference
	- transformer has many repeating blocks, outputs of each layer = intermediate representation of the inputs for next layer
		- class of techniques sometimes called dynamic inference - inference compute determined dynamically 
		- MoE is an example 
- can reduce compute in inference by exiting at an intermediate layer
	- then using that as final output 
- can be done in 2 ways:
	- sequence level early exit = train adapters over each layer to dynamically decide when to exit 
		- e.g. FastBERT - uses binary classifiers (exit or not exit)
	- token-level early exit = different tokens of same sequence can exit at different layers 
		- more complex to implement 
## 2.2 Accelerating Decoding
- decoding using autoregressive models imposes a sequential limitation
	- need to wait for last token to finish to begin next token 
### 2.2.1 Speculative decoding 
- <mark style="background: #FFB8EBA6;">speculative decoding</mark> = smaller model (draft model) used to generate several candidate output tokens
	- main larger model then computes conditional probabilities of candidates
		- using these to decide which tokens to accept/reject
		- more accepted draft tokens == better draft model 
	- 2 metrics here = token acceptance rate + decoding speedup 
- <mark style="background: #FFB8EBA6;">parallel decoding</mark> = generating several output tokens at once 
	- can be done using same model (multi-token decoding) or multiple instances of same model 
	- e.g. Medusa - additional decoding heads added to model, represent subsequent tokens to generate
		- standard transformer predicts $n+1^{th}$ token
		- Medusa has heads for $n + 1, n + 2 ...$ tokens 
## 2.3 Reducing Storage Needs
- forward pass of LLM involves many numeric operations e.g. inputs, weights, activations etc 
	- these are represented using different levels of precision 
- types of numerical representations 
	- <mark style="background: #FFB8EBA6;">FP32</mark> = float 32 = single precision floating point 
		- 32 bits == 4 bytes
		- 3 parts including sign bit (1 bit), exponent (8 bits), mantissa/significand (23 bits)
		- max representation = $3.402.. \times 10^{38}$ and $1.175... \times 10^{-38}$
	- <mark style="background: #FFB8EBA6;">FP16</mark> = float16 = half-precision 
		- reduces exponent to 5 bits, mantissa to 10 bits 
	- <mark style="background: #FFB8EBA6;">BF16</mark> = prevents massing loss in precision for FP16
		- uses 8 bits for exponent, 7 for mantissa
		- keeps possible range same as FP32 with less precision 
- <mark style="background: #FFB8EBA6;">quantisation</mark> = converting representation from higher precision format to lower precision format
	- can quantise 32 bit values to 8 bit integer formats
	- reducing memory requirements by 4x, however can only represent numbers between -127 to 127 (no decimals)
		- integer quantisation can be done symmetrically or asymmetrically 
- quantisation can be used in both training + inference
	- typically done after training - where both weights + activations can be quantised 
		- weights much easier to do than activations
