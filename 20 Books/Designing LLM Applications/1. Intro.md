# 1 Defining LLMs
- <mark style="background: #FFB8EBA6;">language model</mark> = approximates human language, and is built by training over a large body of text
	- imbuing it with properties of language e.g. grammar (syntax), meaning (semantics)
- transformer architecture + next token prediction underpins all types of sequential modelling
	- any concept that can be encoded in discrete sequences w finite vocab can be trained
# 2 Scaling Laws
- 2019, Kaplan et al found increasing LLM size predictably improved performance
	- with no saturation point in sight
	- lead to mathematical formula of scaling laws to be found 
- early 2020, Kaplan et al (OpenAI) - studies scaling laws further, finding power-law relationship between 4 factors
	- model loss, dataset size, compute size, model size (num params)
- 2022, DeepMind argued Kaplan underestimated impact of data size
	- saying current LLMs significantly undertrained, dataset size should be increased at same proportion of model size 
	- led to more models being trained on even larger datasets
# 3 Brief History of LLMs
- Pre-2017, each task was usually solved with a task-specific architecture e.g. CNNs, RNNs etc
	- after 2017 and after with transfer learning success, transformer models allowed for universal model paradigm 
- GPT series by OpenAI first to make LLMs very popular 
	- <span style="color:rgb(255, 136, 0)">GPT-1</span> - demonstrated unsupervised pre-training on large scale data, followed by task-specific supervised fine-tuning
	- <span style="color:rgb(255, 136, 0)">GPT-2</span> - one of the first models to be trained on large-scale web data, showed that pre-trained models could solve a variety of tasks _zero-shot_ 
	- <span style="color:rgb(255, 136, 0)">GPT-3</span> - popularised in-context/few-shot learning
	- <span style="color:rgb(255, 136, 0)">GPT-4</span> - introduced alignment training 
	- <span style="color:rgb(255, 136, 0)">o1</span> - new family focused on reasoning via inference-time compute

# 4 LLMs in the Enterprise
- key ways in which LLMs are used in the enterprise:
	- productivity e.g. Github CoPilot, Marketing, QA over docs
	- report generation e.g. summarisation, financial reports, meeting transcripts
	- chatbots e.g. customer service agents or documentation
	- info extraction e.g. tagging data, NER etc 
	- translation e.g. unstructured to formal text
	- workflows and agents 
# 5 Prompting
- recall, LLMs are next word predictors
	- text they generate is heavily dependent on the text they are fed:
		- the input (prompt)
		- output tokens generated by model so far
		- collectively called context
	- by feeding LLM right context, you're priming it to generate what output you want
		- i.e. _What would be the best prefix of N tokens that when fed to an LLM, will lead it to generate the correct answer with the highest probability?_
	- language models are insensitive to word order
- types of prompting 
	- zero-shot
		- provide instruction concise + explicit manner
		- describe output space, acceptable values, format
		- prime it to generate output e.g. prefixing output
	- COT
		- generate the process to get to the answer instead of directly generating the answer
		- might involve creating subtasks + solving them sequentially 
	- prompt chaining
		- break task into subtasks, chain prompts where output gets fed to next input
		- consistently does better than monolithic
