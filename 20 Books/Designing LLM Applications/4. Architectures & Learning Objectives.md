# 1 Neural Nets as the Foundation
- every LLM based on neural networks
	- dominant Transformer architecture 
		- but others like MoE + state space models have been promising
	- neural nets comprised of processing units = neurons
		- architecture = structure of neurons + how they connect to each other
	- early 2010s saw proliferation of multi-layer architectures
		- many stacked layers of neurons, each layer extracting progressively more complex features of input
- LLMs primarily pre-trained via self-supervised learning
	- input text tokenized into vectors, then propagated through network affected by weights + activation functions
		- activation functions allow for non-linearity 
	- model output compared to expected output, weights adapted via gradients + updates
		- adaptation process implemented via loss function
		- goal of model = to minimise loss (difference between model prediction + gold truth)
		- weight updates done via gradient-based method (backprop)
# 2 Representing Meaning
- embeddings are key to all this
	- representation learning = developing right representations for modalities e.g. text 
	- embeddings often initialised from scratch randomly e.g. Glorot, He etc 
- key idea = how list of numbers can represent meaning 
	- form of a word usually gives no info whatsoever about it's meaning e.g. umbrella
	- <mark style="background: #FFB8EBA6;">distributional hypothesis</mark> = prominent way to represent meaning via numeric form 
		- words that have similar meaning occur in similar contexts 
		- exemplified by John Firth adage, 1957 - "*You shall know a word by the company it keeps*"
- distributional hypothesis fundamental in self-attention
	- self-attention generates vector representation of each token in a sequence 
		- that encapsulates meaning of a token 
	- vector representation of a token = function of representations of all tokens in the sequence
		- tokens with similar meaning/connotations have vectors closer to each other 
# 3 Transformer Architecture
- mid 2010s, predominant NLP architecture was RNNs then LSTMs
	- sequence models which processed 1 token at a time, with a single vector to represent state of the sequence 
	- because of this, longer range dependencies harder to capture
		- "*You can’t cram the meaning of a whole %&!$# sentence into a single $&!#* vector!*" - Ray Mooney
- Transformers solved for deficiencies - long-range dependencies, single vector dependence and more
	- transformer block/layer has 4 key components 
		1. self-attention
		2. positional encoding
		3. feed-forward networks
		4. normalisation blocks
## 3.1 Embedding Layer
- embedding layer - at the very start of the network, input tokens mapped to corresponding vectors
	- embedding layer is a matrix with the size = $\text{Sequence Length} \times \text{Vector Dimension}$
	- can inspect embedding layer in 🤗 like so:

```python
import torch
from transformers import LlamaTokenizer, LlamaModel

tokenizer = LlamaTokenizer.from_pretrained('llama3-base')
model = LlamaModel.from_pretrained('llama3-base')

sentence = "He ate it all"

inputs = tokenizer(sentence, return_tensors="pt")
input_ids = inputs['input_ids']
tokens = tokenizer.convert_ids_to_tokens(input_ids[0])

with torch.no_grad():
    embeddings = model.embeddings(input_ids)

for token, embedding in zip(tokens, embeddings[0]):
    print(f"Token: {token}\n
    print(f"Embedding: {embedding}\n")
```

## 3.2 Self-Attention
- operationalises the distributional hypothesis
	- generates representations for each token of text capturing various aspects of language e.g. syntax, semantics, pragmatics 
- **representation of each token = function of representation of all other tokens in the sequence**
	- given a token to process, tokens in the sequence that contribute more towards the meaning are given more weight 
- the self-attention process
	1. each token represented by embedding vector
	2. embedding vector $X$ is multiplied with $\textcolor{blue}{\text{Query}}$, $\textcolor{red}{\text{Key}}$ and $\textcolor{green}{\text{Value}}$ weight matrices 
		- generates 3 new/additional input vectors 
			- $\textcolor{blue}{\text{Query}}$: $\textcolor{blue}{Q_i} = X \cdot W_Q$ 
			- $\textcolor{red}{\text{Key}}$: $\textcolor{red}{K_i} = X \cdot W_K$ 
			- $\textcolor{green}{\text{Value}}$: $\textcolor{green}{V_i} = X \cdot W_V$ 
	3. for each token, calculate ***dot product*** of the $\textcolor{blue}{\text{Query}}$ vector with the $\textcolor{red}{\text{Key}}$ vectors of all other tokens (inc. itself)
		- these are the attention scores
	4. attention scores then scaled by ***dividing them by square root*** of dimension of $\textcolor{red}{\text{Key}}$ vectors
		- to normalise for longer sequences
	5. attention scores then passed through ***softmax function*** 
		- to turn them into a probability distribution that sums to 1 
		- tends to amplify larger values hence need for scaling above
	6. normalised attention scores then multiplied by the $\textcolor{green}{\text{Value}}$ vector for the corresponding token 
		- interpreted as % each token contributes towards the representation of a given token 

$$
\begin{gather}
\large
\text{Self-Attention} \\ \ \\
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{Q \cdot K^T}{\sqrt{d_k}}\right) V
\end{gather}
$$
- in practice, we use multiple sets of $\textcolor{blue}{\text{Query}}$, $\textcolor{red}{\text{Key}}$ and $\textcolor{green}{\text{Value}}$ weight matrices 
	- aka <mark style="background: #FFB8EBA6;">Multi-headed Self-Attention</mark>
	- allows us to calculate parallel representations - so model gets sufficient capacity to learn various aspects of the input
	- more heads = more chance that the right aspects of the input are represented

```python
# self attn in code
import torch
import torch.nn as nn
import torch.nn.functional as F

q = wQ(input_embeddings)
k = WK(input_embeddings)
v = WV(input_embeddings)
dim_k = k.size(-1)

attn_scores = torch.matmul(q, k.transpose(-2, -1))
scaled_attn_scores = attn_scores/torch.sqrt(torch.tensor(dim_k, dtype=torch.float32))

normalized_attn_scores = F.softmax(scaled_attn_scores, dim=-1)

output = torch.matmul(normalized_attn_scores, v)
```

## 3.3 Positional Encoding
- since transformers do parallel computation, they lack positional info like RNNs
- so need to explicitly give it positional info - active field of research with multiple kinds used
	- <span style="color:rgb(255, 0, 247)">Absolute positional embeddings</span> = used in original, using sinusoidal functions
	- <span style="color:rgb(255, 0, 247)">ALiBi</span> (Attention w Linear Biases) = attn scores penalised w bias proportional to distance between Query + Key token
		- enables longer sequence length modelling than what was used in training process
	- <span style="color:rgb(255, 0, 247)">RoPE</span> (Rotary Position Embedding) = also has property of relative decay like ALiBi
		- decay in attn scores as distance between Query + Key token increases
	- <span style="color:rgb(255, 0, 247)">NoPE</span> (No Positional Encoding) = contrarian technique arguing positional embeddings not needed
		- and that transformers implicitly capture it
- today, most people using RoPE, ALiBi
## 3.4 Feedforward Networks
- output from self-attention block then passed into FFNN
	- each token representation *independently* fed into the network 
		- hence some call it position-wise FFNN
	- FFNN uses non-linear activation function e.g. ReLU, GeLU
		- allowing model to learn more complex features from the inputs

```python
import torch
import torch.nn as nn

class FeedForward(nn.Module):
    def __init__(self, input_dim, hidden_dim):
        super(FeedForward, self).__init__()
        self.l1 = nn.Linear(input_dim, hidden_dim)
        self.l2 = nn.Linear(hidden_dim, input_dim)
        self.selu = nn.SeLU()

    def forward(self, x):
        x = self.selu(self.l1(x))
        x = self.l2(x)
        return x

feed_forward = FeedForward(input_dim, hidden_dim)
outputs = feed_forward(inputs)
```

## 3.5 Normalisation Blocks
- <mark style="background: #FFB8EBA6;">Layer Normalisation</mark> = ensures training stability + faster convergence
	- original transformer used pre-norm, modern implementations use post-norm 
- process of applying layer norm 
	1. given input with following size 
		- batch size = $b$
		- sequence length = $n$
		- vector dimension = $d$
	2. calculates mean and variance across each vector dimension 
	3. normalise input by subtracting mean + divide by square root of variance (standard deviation)
		- small epsilon value added to denominator for numerical stability 
	4. multiply by scale parameter + add a shift parameter to resulting values
		- these scale + shift params are learned during training process 

```python
import torch
import torch.nn as nn

class LayerNorm(nn.Module):
    def __init__(self, dimension, gamma=None, beta=None, epsilon=1e-5):
        super(LayerNorm, self).__init__()
        self.epsilon = epsilon
        self.gamma = gamma if gamma is not None else
        nn.Parameter(torch.ones(dimension))
        self.beta = beta if beta is not None else
        nn.Parameter(torch.zeros(dimension))


    def forward(self, x):
        mean = x.mean(-1, keepdim=True)
        variance = x.var(-1, keepdim=True, unbiased=False)
        x_normalized = (x - mean) / torch.sqrt(variance + self.epsilon)
        return self.gamma * x_normalized + self.beta

layer_norm = LayerNorm(embedding_dim)
outputs = layer_norm(inputs)
```

## 3.6 Loss Functions
- with all the components, we propagate inputs to predict the next token 
	- output/prediction will be a probability distribution across all tokens 
- loss function calculated by comparing input distribution with gold truth 
	- gold truth = one-hot vector with 1 for gold-truth token, 0 for all others 
	- <mark style="background: #FFB8EBA6;">cross-entropy loss</mark> = most popular way to quantify difference between output + gold-truth
	- you will see this represented many different ways, so I've covered most 

$$
\begin{gather}
\Large
\text{Cross-Entropy Loss} \\ \ \\
\large\text{CE}_{loss} = - \sum_{i = 1...V} y_i \ \log \hat{y_i} \\ \ \\
\textit{or} \\ \ \\ 
\large H(p,q) = - \sum\limits p(x) \ \log q(x) \\ \ \\
\textit{or} \\ \ \\ 
\large{\text{CE}_{loss} = - \sum\limits \small{\text{Gold-Truth Probability}} \times \log \small{(\text{Output Probability})}}
\end{gather}
$$

- with loss calculated, gradient of the loss w.r.t. parameters of model calculated
	- then weights updated via backprop 
# 4 Intrinsic Model Evaluation
- extrinsic vs intrinsic model evals
	- extrinsic = test performance of model on real-world downstream tasks
	- intrinsic = more generally evaluating ability to model language 
		- no direct guarantee that promises downstream performance, but often correlated
- <mark style="background: #FFB8EBA6;">perplexity</mark> = most common intrinsic metric 
	- measures ability of LM to predict next token in sequence 
	- model that always correctly predicts = perplexity of 1
		- higher perplexity == worse LM can predict next word
		- worst case - random prediction = size of vocab
	- very much related to cross entropy loss - calculated as $PPL = 2^{CE_{loss}}$
# 5 Transformer Backbones
## 5.1 Encoder, Decoder, Encoder-Decoder
- 3 major types of transformers since the original 
	- <span style="color:rgb(255, 0, 247)">encoder only</span> 
		- less trained these days - harder to train, MLM objective is less efficient (needs more data), need task-specific heads for each downstream task
		- still great choices for classification tasks
		- some tips for adopting encoder only models
			- RoBERTa > BERT - trained longer, more data + uses best practices learned after BERT
			- DeBERTa considered best + has largest size (1.5B)
			- distilled versions e.g. DistilBERT very good, close to original performance while much smaller/faster
		- many embedding models often built on encoder-only
			- e.g. `sentence-transformers` provides encoder embedding models e.g. "*all-mpnet-base-v2*"
	- <span style="color:rgb(255, 0, 247)">encoder-decoder</span>
		- original architecture as first proposed - T5 series of model uses this architecture 
		- input and output are both text, inputs handled by encoder, outputs by decoder 
	- <span style="color:rgb(255, 0, 247)">decoder only</span> 
		- most popular for LLMs today, came into fashion after original GPT model from OpenAI
			- excels at zero + few shot learning
		- decoder models can be causal and non-causal 
			- **causal decoder** = only look backwards (left)
			- **non-causal decoder** = bidirectionally over input sequence, output still autoregressive
- compelling studies shown best results:
	- decoder only best for zero-shot + few-shot generalisation
	- encoder-decoder best for multi-task finetuning 
## 5.2 Mixture of Experts (MoE)
- another promising architecture - most SOTA models based on this e.g. GPT4, DeepSeek R1
	- remarkable since 2017 transformer implementation largely unchanged, surprisingly robust
	- scaling laws dictate performance increases with increase to model + data size
		- but increasing model size == more compute for both training + inference (often undesirable)
- how to increase capacity without increasing needed compute?
	- <mark style="background: #FFB8EBA6;">conditional computation</mark> = each input sees different subset of model
		- interacting with only parameters best suited to process it 
	- achieved with architecture using several components (**experts**)
	- only a subset of experts activated for each input 
- key component in MoE = <mark style="background: #FFB8EBA6;">gating function</mark> - helps decide which expert best suited to process given input 
	- gating function implemented as weight applied to each expert 
	- experts typically added to just FFNN part
		- 8 experts = 8 separate FFNNs instead of 1 
		- but due to routing strategy, only small subset of networks activated for given input 
- <mark style="background: #FFB8EBA6;">routing strategy</mark> = determines number + which experts to activate
	- 2 popular routing strategies 
		- <span style="color:rgb(255, 0, 247)">tokens choose</span> = each token chooses $k$ experts (e.g. 2)
			- pitfall = need for load balancing, if given input batch and most tokens use same expert, more time needed to compute
			- hence no benefit from parallelisation of multiple experts
		- <span style="color:rgb(255, 0, 247)">experts choose</span> = each expert picks tokens best equipped to handle 
			- solves load balancing, each expert chooses same number of tokens
			- but leads to inefficient token-expert matching since they limited to only picking finite num tokens in batch
# 6 Learning Objectives
- self-supervised is main method - helps with prohibitive cost of labelled data needs
	- <mark style="background: #FFB8EBA6;">goal of self-supervised</mark> = **learn a task as proxy for learning syntax + semantics of language + other skills**
		- similar to how younger kids first learn basics of english etc 
	- predicting the next token - very powerful tool 
		- can gradually learn more complex functions to encode in model connections
		- open question if next token prediction == path to AGI 
- 3 types of self-supervised learning objectives
	- <span style="color:rgb(255, 0, 247)">FLM (full language modelling)</span>
		- simplest + most common - predict next token 
		- loss computed for every token seen, making it very efficient 
	- <span style="color:rgb(255, 0, 247)">MLM (masked language modelling)</span>
		- predict masked tokens in a sequence 
			- e.g. BERT used 15% randomly masked tokens which were replaced with special `<MASK>` token
			- to try recover/predict what the original token was 
		- computationally cheaper (less train time) but less sample efficient 
		- MLM interpreted as **denoising autoencoder**
			- corrupting embedding with noise, then training to regenerate original 
	- <span style="color:rgb(255, 0, 247)">PrefixLM (Prefix language modelling)</span>
		- similar to FLM but fully causal, i.e. cannot attend to future tokens 
		- prefix part therefore non-causal, trained using random prefix length sampled, then loss calculated on suffix tokens
- which learning objectives are better?
	- training with FLM = better for generation
	- training with MLM = better at classification
	- UL2 = inefficient to use different LMs for different use-cases, tries to combine all into single model
		- mimics effects of FLM, MLM, PrefixLM into single paradigm = mixture of denoisers 
# 7 Pre-training Models
- LLMs learn 2 broad types of concepts through text today
	- language - vehicle for communicating facts, opinions, feelings
	- underlying phenomena that led to construction of text in the language 
		- this is often more important 
- such concepts shown in language through tasks like arithmetic + reasoning
	- however human language often ambiguous, has redundancies, and generally inefficient
		- e.g. LeCunn saying it is low bandwidth vs video etc - but often more compact 
	- so are human languages best vehicle for learning skills + concepts?
		- probably not - e.g. chess experiments trained with 2 models
			- one in english, one in chess moves - english version much worse
