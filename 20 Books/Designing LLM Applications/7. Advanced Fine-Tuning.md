- recall, multiple reasons you'd want to update parameters of an LLM
	- <span style="color:rgb(255, 0, 247)">domain adaptation</span> = data from specialised domain LLM probably didn't see in pre-training
	- <span style="color:rgb(255, 0, 247)">task adaptation</span> = improving LLM on specific downstream task of interest (supervised or unsupervised)
	- <span style="color:rgb(255, 0, 247)">knowledge updating</span> = to keep LLM knowledge up-to-date by continually training on new data 
	- <span style="color:rgb(255, 0, 247)">controllability/steer-ability</span> = to control LLM behaviour - alignment training 
- various techniques 
	- <span style="color:rgb(255, 0, 247)">continual pre-training</span> = primarily used for domain adaptation + up-to-date knowledge
	- <span style="color:rgb(255, 0, 247)">PEFT</span> = efficient way of performing fine-tuning
	- <span style="color:rgb(255, 0, 247)">model merging/fusion</span> = new subfield to combine parameters of models together 
		- aka the *dark arts of NLP* - often poorly understood but can be very effective
# 1 Continual Pre-training
- challenging due to <mark style="background: #FFB8EBA6;">catastrophic forgetting</mark> = LLM _forgets_ its previously learned capabilities and knowledge when it is continued to be trained on new and different data
- learning objectives and datasets for continual PT
	- continual PT performed in self-supervised manner (like pre-training)
	- uses the same learning objective as original pre-training setup 
	- uses data orders of magnitude larger than typical FT datasets 
## 1.1 Data for Continual pre-training
- for domain adaptation, often need data that is most representative of the domain 
	- a domain can be described as text whose representations form an implicit cluster
- approaches to curating CPT data
	1. **select data using embedding similarity with gold-truth in-domain data** 
	2. **fine-tune domain classifier to predict gold-truth in domain vs random negative samples**
- techniques to avoid catastrophic forgetting 
	- <span style="color:rgb(255, 0, 247)">replay (memory)</span> = interweaves training examples from original pre-train mix with new data
	- <span style="color:rgb(255, 0, 247)">distillation</span> = takes older checkpoint of model during training + uses KLD
		- compares KL divergence between older and current representations + penalises it 
	- <span style="color:rgb(255, 0, 247)">regularisation</span> = penalises large changes to params during CPT
	- <span style="color:rgb(255, 0, 247)">parameter expansion</span> = adds more params to model as CPT is performed
		- can be done by increasing width or depth of the model 
		- can also insert + train domain-specific parameter modules (adapters) within existing layers
		- MoE can also be useful here since experts trained separately without effecting others 
- replay is most common technique but need to manage learning rate effectively 
	- ideal LR is tradeoff between how much forgetting you can tolerate vs how much new knowledge you want
		- if LR too small, model retains existing capabilities but fails to learn from new data 
		- if LR too large, model learns from new data at expense of forgetting previous capabilities 
	- studies show effective LR schedule - re-warm LR at start of continual learning to maximum learning rate
		- then decay it with cosine schedule until it reaches minimum LR
		- after which, LR kept constant 
		- max LR chosen to balance tradeoff between forgetting + learning
- summary - continual PT very effective when you have: 
	- large body of domain-specific text
	- which is distinctly characterised by specialised linguistic structure or vocabulary 
	- can also add extra tokens to represent domain-specific jargon 
# 2 Parameter-Efficient Fine-Tuning
- 3 kinds of PEFT techniques
	- <span style="color:rgb(255, 0, 247)">adding new params</span> = adding some extra params to LLM, and training only them
	- <span style="color:rgb(255, 0, 247)">selecting subset of params</span> = choosing to update only small subset, by selecting them apriori or learning best subset
	- <span style="color:rgb(255, 0, 247)">low-rank methods</span> = methods to reduce number of params by training to find smaller matrix containing almost the same info as larger matrix 
## 2.1 Option 1: Adding new parameters
- adds few extra params to model and trains only them
	- avoids storing + deploying full copies of each fine-tuned model
- common ways to add new params for fine-tuning:
	- <span style="color:rgb(255, 0, 247)">bottleneck adapters</span> = lightweight modules added to transformer layers
		- most common way to adapt modules into LLM is via transformer layers
			- only adapter modules trained in FT, original pre-trained model not updated
		- to reduce number of params, width of adapter should be much less than width of underlying transformer model
			- known as a *down-projection* or *bottleneck*
		- bottleneck adapter sub-layer has: 
			- a down-projection matrix = to reduce params
			- an up-projection matrix = at the end to project back to original params 
			- parameters that can be configured in a variety of ways in the middle
		- adapters often initialised with near-identity initialisation for smooth trainig
	- <span style="color:rgb(255, 0, 247)">prefix tuning</span> = task specific vectors trained + prefixed to input
		- for adapter methods, each batch can only support single adapter
			- prefix-tuning enables multiple tasks to be run in same batch 
		- adds + trains task-specific vectors to the prefix of the input 
			- recall, LLM conditioned on previous outputs to generate new text 
			- can add additional context LLM can attend to in form of prefix vectors 
				- new tokens prefixed known as *virtual tokens* or *soft prompts*
	- <span style="color:rgb(255, 0, 247)">prompt tuning (soft prompts)</span> = similar to prefix, but w simplified training approach 
		- simplified version of prefix-tuning
		- unlike prefix tuning, there are no prefix parameters at each layer
## 2.2 Option 2: Selecting a subset of parameters
- naive approach = finetune only upper layers of transformer, freeze everything else 
	- lower layers known to focus on more fundamental language aspects e.g. syntax - we want to preserve 
- there is research to show FT only exposes existing capabilities of models, not new capabilities 
	- this means there might exist a subset of params particularly suited to each downstream task 
	- one study proposes applying a binary mask that is trained per task to apply

# 3 Model Merging & Fusion
- overlapping in terms of capabilities yet possess certain unique characteristics
	- done by a variety of means, including model ensembling and model fusion or merging
	- dark arts since underpinnings of this remain poorly understood 
## 3.1 Model ensembling 
- each LLM may have different but complementary capabilities 
	- caused by consequences of their training data, training regimes, hyperparams etc 
- recall, we can generate multiple outputs for same input + select the best
	- can also do this at the LLM level - LLM ensembling
- LLMBlender = framework to enable this, 2 components:
	- <span style="color:rgb(255, 136, 0)">PairRanker</span> - scores output from 2 models, choosing a winner
		- PairRanker module is trained to provide scores for each of the outputs
		- feeding all the pairs of outputs to the PairRanker module, you will then find the output (model) with the highest score
		- however this just selects the best, not necessarily combines their capabilities 
	- <span style="color:rgb(255, 136, 0)">GenFuser</span> - uses output from K different models as input to generate final output 
		- take the top K results from the PairRanker scores + feed them to GenFuser module to generate final output 
		- GenFuser in practice is just a fine-tuned LLM that is tuned to accept several candidate inputs and generate an output that combines the characteristics of the different candidates
```python
import llm_blender
from llm_blender.blender.blender_utils import get_topk_candidates_from_ranks

ensemble = llm_blender.Blender()
ensemble.loadranker("llm-blender/PairRM")
ensemnle.loadfuser("llm-blender/gen_fuser_3b")

rank_list = blender.rank(input, candidate_outputs)
top_k = get_topk_candidates_from_ranks(rank_list, candidate_outputs, top_k=4)
final_output = ensemble.fuse(input, top_k)
```
## 3.2 Model Fusion
- combine the parameters of multiple models in some way
	- intuitively trying to benefit from all the complementary capabilities of each model - within a single model 
- common methods of model fusion
	- averaging = simplest way to combine multiple models is to average their parameters together
	- weighted averaging = during averaging, certain models or even certain layers in models can be weighted more
	- interpolation = each model can be weighted by a factor $w_{1}, w_{2}, ... w_{n}= 1$
