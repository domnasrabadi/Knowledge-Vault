# 1 What is Alignment Training
- goal of alignment is to make language models more controllable and steerable
	- Askell et al. from Anthropic define an aligned AI as one that is _helpful, honest, and harmless_
# 2 Reinforcement Learning with Human/AI Feedback
- values and principles we need the LLM to adhere to are defined by humans, and involve a level of subjectivity
	- makes sense to optimise on human feedback - RLHF 
	- in RLHF, the feedback is provided by a human-in-the-loop in an iterative fashion
	- to integrate human preferences into the LLM, a _reward model_ needs to be trained
## 2.1 Types of Human Feedback 
- forms of human feedback:
	- <span style="color:rgb(255, 0, 247)">binary feedback</span> = yes/no, accept/reject 
	- <span style="color:rgb(255, 0, 247)">binary comparisons</span> = preferences between A vs B 
	- <span style="color:rgb(255, 0, 247)">ranking</span> = rank ordering preferences 
	- <span style="color:rgb(255, 0, 247)">corrective feedback</span> = explicitly stating what would have been ideal 
## 2.2 RLHF Example
- a popular RLHF setup pioneered by OpenAI - 3 stages:
	1. <span style="color:rgb(255, 0, 247)">Supervised fine-tuning</span> = Fine-tune a pre-trained model on a dataset created from diverse user prompts and human-annotated responses, requiring significant annotation effort
	2. <span style="color:rgb(255, 0, 247)">Reward modelling</span> = Generate multiple responses per prompt and use human feedback (rankings or selections) to train a reward model that predicts preferred outputs
	3. <span style="color:rgb(255, 0, 247)">PPO (Proximal Policy Optimisation)</span> = Utilise the reward model to further optimise the fine-tuned model with PPO, aligning its outputs more closely with human preferences
- PPO training done as follows:
	1. LLM generates response/continuation to prompt 
	2. reward model takes query + response, outputs scalar reward (quality of input)
	3. log probs of tokens in query-response sequence calculated 
		- using model being tuned (SFT model) and reference model (usually base model)
		- KL divergence between 2 log-probs calculated + used as signal with the reward
		- to prevent outputs deviating too much from reference model (acts as regulariser)
	4. model trained via PPO objective, using signals from step 2 + 3

# 3 Hallucinations 
- <mark style="background: #FFB8EBA6;">hallucination</mark> = LLM generates text that is inconsistent with either its pre-training/fine-tuning data or input context
	- commonly manifest as text with no factual basis
- Fine-tuning data on new knowledge can increase the tendency of the model to hallucinate
	- also show that when learning the new knowledge leads to overfitting, causing an increase in hallucinations for even unrelated questions
	- studies show larger models posses more self-knowledge
		- and instruct-tuned models more self-knowledge than base models 
## 3.1 Mitigating Hallucinations
- ideally LLMs should acknowledge lack of knowledge when asked about a fact or concept it genuinely doesn't know
	- e.g. unknown unknowns 
	- can identify potential hallucinations via model's uncertainty 
		- i.e. via output probabilities - but assumes model is well calibrated i.e. probabilities correlate to the outcome
- RAG is one approach to solving for hallucinations - grounding in factual data sources 
	- feeding facts in the prompt does not eliminate them, especially with larger contexts
	- using RAG shifts bottleneck towards retrieval, lack of good retrieval can make answers worse 
- Prompting methods
	- <mark style="background: #FFB8EBA6;">self-consistency</mark> = generate output multiple times, detect inconsistencies between them 
		- e.g. answer consistency 
	- <mark style="background: #FFB8EBA6;">chain-of-actions</mark> = aka Self-Verification e.g. Chain of Verification from Meta
		- model generates response
		- another model generates verification questions given prompt + response
		- each verification question sent to separate model, then compared against original response 
	- <mark style="background: #FFB8EBA6;">recitation</mark> = prompt LLM to generate several passages for a question, then use self-consistency for each candidate response
		- can be more effective than COA
- Sampling approaches
	- decoding method also affects this e.g. top-p sampling causes more than greedy 
	- <mark style="background: #FFB8EBA6;">factual-nucleus sampling</mark> = as length of generated sequence increases, fewer valid candidate tokens for next generation
		- so randomness of sampling gets reduced as text gets longer 
		- has 3 tuneable params (decay rate, reset, lower-bound)
	- <mark style="background: #FFB8EBA6;">DoLa</mark> (Decoding by Contrasting Layers) = principle behind this is factual knowledge encoded in topmost layers of transformer, like syntactic info encoded in lower layers
		- can then emphasise knowledge in higher layers to promote factuality 
		- achieved via contrastive decoding - next token prob for each token calculated via difference in logits between higher and lower layer
## 3.2 In-context Hallucinations
- <mark style="background: #FFB8EBA6;">in-context hallucinations</mark> = model hallucinates based on data provided in the context 
	- particularly prevalent in RAG settings
	- can also be caused by including irrelevant info in the context 
- mitigations
	- <mark style="background: #FFB8EBA6;">Lookback Lens</mark> =using attention maps to detect hallucinations
		- calculates lookback ratio (ratio of attn weights on context tokens to attn weights on newly generated tokens)
			- calculated at each attention head of each layer in model
			- ratios then used as features to train linear classifier 
		- can also be employed to reduce hallucinations in generation
			- in generation, generates a few candidate sequences
			- lookback ratio calculated + fed to model, choose lowest probability sequence
	- <mark style="background: #FFB8EBA6;">S2A (System 2 Attention)</mark> = LLM is first asked to regenerate its context, removing any information irrelevant to answering the question
		- then LLM is prompted with the regenerated context and the final answer is generated
# 4 Reasoning
- reasoning can be classified into several types (non mutually exclusive)
	- <mark style="background: #FFB86CA6;">deductive</mark> = uses logic to draw conclusions from one or more premises
	- <mark style="background: #FFB86CA6;">inductive</mark> = involves making generalisations based on a set of observations
		- only plausible and probabilistic than guaranteed, based on the strength of the observations
	- <mark style="background: #FFB86CA6;">abductive</mark> = involves analysing a set of observations and concluding with the most likely explanation
	- <mark style="background: #FFB86CA6;">common sense</mark> = using understanding of the world to make assumptions about the physical world/human relationships
		- relies on implicit knowledge of the world, often not verbalised
- stochastic parrots or reasoners?
	- one school of thought - does not matter if models are just sophisticated pattern matchers
		- good enough if they can solve the task
		- and we also do not know enough on how the human brain does reasoning
	- however, understanding the low level details when they supposedly reason is also very important
		- helps understand current limitations of LLMs + intuit what classes of problems can be solved 
- how to induce reasoning 
	- verifiers can improve reasoning - using iterative candidates + verification rather than solving whole
	- test time scaling - e.g. repeated sampling, iterative generation, augmenting context 
		- shown that more tokens used in reasoning steps - the better model performance
		- also via search methods 
- fine-tuning for reasoning 
	- possible with reasoning datasets - contains step-by-step reasoning chains for many tasks
	- can be generated synthetically, and human annotated or RL completely
