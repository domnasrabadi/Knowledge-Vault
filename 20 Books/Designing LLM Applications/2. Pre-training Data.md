# 1 LLM Ingredients 
- **Pre-training Data** = what is it trained on? 
    - Quality of data is critical; the adage “Garbage In, Garbage Out” applies.
    - Preprocessing ensures high-quality data; tools and techniques assess pre-training data's impact on downstream tasks.
- **Vocabulary and Tokenizer** = what is it trained over?
    - Define vocabulary and rules to tokenize text effectively.
    - Human language is processed in terms of meaning (words, sentences); LLMs use tokens.
    - Misalignment between human language processing and tokens can affect downstream performance.
- **Learning Objective** = what is it being trained to do?
    - Pre-training imparts general skills (syntax, semantics, reasoning) to solve varied tasks.
    - General training objectives influence downstream performance based on task similarity.
- **Architecture** = what is it's internal structure?
    - architecture = how model components interact
	    - each architecture has own inductive biases - assumptions made on data + tasks being used for, which will influence solutions
    - Transformer alternatives address limitations and adapt to specific needs.
- **Popular Tuning Modes**
    - <span style="color:rgb(255, 136, 0)">Supervised Fine-tuning</span>: Improves adherence to instructions.
    - <span style="color:rgb(255, 136, 0)">RLHF</span>: Aligns models with human preferences.
    - <span style="color:rgb(255, 136, 0)">Domain/Task-adaptive Pre-training</span>: Refines models for specific applications.
# 2 Pre-training data requirements
- **Sample Efficiency**
    - LLMs require extensive data due to sample inefficiency
	    - not all data is equal, can get more sample efficiency with higher quality data
	    - e.g. distillation - thus needing smaller dataset sizes 
    - Self-supervised learning mitigates the need for large supervised datasets
	    - <mark style="background: #FFB8EBA6;">self-supervised</mark> = training labels exist within training inputs 
- **Epochs**
    - earliest DL models trained on 1 epoch to prevent overfit
	    - studies shown can increase training size by increasing epochs on same data
	    - models benefit from 4-5 epochs without performance drops but diminish after that
    - mixing high- and low-quality data ensures balance
	    - larger models overfit more easily on multiple epochs - dropout can help 
- **Popular Datasets**
    - **C4 (Common Crawl):** Cleaned web crawl data, foundational for T5.
    - **The Pile:** Diverse sources (PubMed, GitHub, Wikipedia, etc.) enhance generalization.
    - **OpenWebText:** Reddit-linked high-quality pages.
    - **Wikipedia:** Structured factual data; lacks stylistic diversity.
    - **BooksCorpus:** Fiction-heavy corpus for BERT, GPT-2/3.
    - **FineWeb:** HuggingFace dataset (15T tokens) combining rigorous filtering.
- **Trends**
    - Increasing restrictions on data usage due to updated website policies
    - Synthetic data (e.g., Microsoft Phi, HuggingFace Cosmopedia) as a growing pre-training source
	    - Phi 1.5 created 20B tokens of synthetic data with 20k seed topic from real seed data in their prompts
# 3 Training data preprocessing
- key steps in data preprocessing
	- note: these are not sequential + can be dependent within steps 
- <span style="color:rgb(255, 0, 247)">Data Filtering & Cleaning</span>
    - remove boilerplate
	    - only lines ending with proper punctuation kept to remove things like menu items fom sites
	    - removing text that has "lorem ipsum" etc 
		- Meta used custom HTML parser to prepare Llama 3 data
		    - also kept alt attribute in images which included useful info like math content 
    - SEO + spam text removal 
	    - removing lots of repeated character sequences
	    - docs with low % of closed class words removed e.g. "of", "it", "is" - common in SEO
    - non-english text removal 
	    - e.g. using `langdetect`, `langid`, `fasttext`, `pycld2`
	- sexual/violent text removal - using keyword lists
- <span style="color:rgb(255, 0, 247)">Quality Selection</span> - several ways to operationalise notion of quality docs 
    - *K-L Divergence*: removes docs with token distribution deviating too much from reference distribution
    - *Classifiers*: build classifier for identifying high quality data 
	    - e.g. trained on examples of positive class from high quality data sources 
	    - Llama 3 used `fasttext` classification model to identify if text likely referenced by wikipedia 
		    - also trained classifier with data generated by Llama 2 providing it cleaned web docs + quality requirements
		    - then asking to determine if quality requirements are met 
		    - also trained classifier to extract data with code + reasoning steps 
    - *Perplexity*: measures how well model can predict given text (lower = better)
	    - has been used to prepare pre-training data by filtering docs 
	    - select docs from high quality data sources, train 5-gram LM over it
	    - next predict on data source = lower perplexity == more similar to high quality training data 
		    - then discard docs with high perplexity 
		    - however short repetitive text can have low P, so can also oversample from middle part of perplexity probability distribution 
- <span style="color:rgb(255, 0, 247)">Deduplication</span>
    - forms non trivial portion of data, so any action here has notable impact on model 
    - types of duplication 
	    - exact matches = easiest to handle
	    - approx matches = near dupes - slight differences
	    - semantic duplicates = same content, different words - usually kept
	- can be categorised on granularity level which they occur 
		- doc level duplicates = dupe docs
		- sequence level duplicates = dupe sentences or lines repeated in single docs 
			- very common in Terms of Service, Copyright notices etc 
	- de-duping benefits
		- removes overlap of train + test - less overfitting 
		- reduces data set size 
		- reduces memorisation
- <span style="color:rgb(255, 0, 247)">PII Removal</span>
    - GDRP: "Protection should be extended to anything used to directly/indirectly identify a person"
	    - e.g. names, addresses, credit card data, govt IDs, medical history, email, phones, identity groups 
    - PII removal very similar to NER detection - PII tags as above 
	    - can also use regex with transformer based NER models 
	- PII remediation
		- replace with special tokens 
		- replace with random token of same entity type 
		- replace with shuffled tokens
		- remove entire doc/data source
	- `faker` = excellent library to facilitate random token replacement 
- <span style="color:rgb(255, 0, 247)">Decontamination</span>
    - when training data contains benchmark eval data 
	    - common both accidental + on purpose 
		- 2 types of contamination - input + labels, inputs only
    - avoid overlap of inputs/labels between training and test datasets for unbiased results
- <span style="color:rgb(255, 0, 247)">Data Mixtures</span>
    - preparing final dataset such that different domains represented in desirable proportions
	    - optimise domain representation in datasets (e.g., 50% general knowledge for Llama 3)
	    - more involved techniques = DoReMi and RegMix - to calculate right mixture 
    - very common today to include code in pre-training data even if model will not be used for it 
	    - studies show including code significantly improves non code related downstream tasks
    - order in which data is fed to model also matters
	    - curriculum learning = area of study to determine most optimal order 
	    - start with shorter training sequences then gradually increase sequence lengths 
	- `datatrove` by HF also very useful library for dataset preprocessing
# 4 Effect of Pre-training data on Downstream Tasks
- there is correlation between model performance on given task + pre-training frequency of that task or salient words
	- LLMs perform best on tasks more represented in training data 
	- also do better with higher frequency inputs vs lower frequency 
# 5 Bias & Fairness in Pre-training
- LLMs amplify biases inherent in pre-training data.
- Values of model providers shape data curation and model output.
- Techniques like pronoun swaps in **Pythia** demonstrated de-biasing impacts.
