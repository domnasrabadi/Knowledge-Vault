# 2 Highlights

- **documentation & knowledge**
    - read all product docs fully, early, and often; annotate with questions and ideas
    - learn your team’s full tech stack (e.g., git, terraform)
    - read old team docs — pentest reports, security evaluations are valuable history

- **baseline systems**
    - set up early: note-taking, doc templates, code storage, screenshots, email rules
    - keep daily end-of-day logs for continuity and as a sign-off habit
    - maintain a **“wins” doc** for performance review material

- **communication & reporting**
    - take notes in meetings; share when useful
    - call out issues early (quick pings to put things on radar)
    - have a shared 1:1 doc with manager for links, PTO, training, growth goals
    - write SOPs for anything confusing or error-prone
    - start an onboarding guide from day one and update it for future hires

- **meeting hygiene**
    - never send vague invites — always include an agenda
    - block work time on your calendar
    - join meetings 1–2 min early, camera on, decent mic/lighting
    - notify if running late

- **work habits**
    - take real lunch breaks (step away, reset)
    - track data at project start to measure impact
    - deliver on commitments — if not possible, communicate early
    - schedule time for admin tasks with a fun playlist
    - use formatting in docs (bold, color, monospace, tables, diagrams) to make skimming effective
    - diagram processes for clarity

- **ergonomics & tools**
    - avoid sitting on foot/cross-legged — back health
    - use a comfortable KVM setup, minimize hardware friction

- **personal organisation**
    - keep a personal scratchpad for non-work to-dos that pop up mid-task

- **learning & improvement**
    - do post-mortems: what happened, what went wrong, what went well, action items
