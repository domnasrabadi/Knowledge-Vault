- One of the primary challenges with tables is their structural complexity. Tables can have merged cells, multi-level headers, and varying data types, making it difficult to accurately extract the relationships between rows and columns.
- For tables, there are two steps. First apply advanced parsing techniques that preserve structural information as much as possible, such as converting tables into structured formats like JSON or Markdown with appropriate metadata.
- Now the question is how to deal with the table. Early RAG implementations often applied the following approach: during ingestion, you send the complete table (say in markdown format) to an LLM with instructions to provide a summary. Then that summary would be ingested, as normal text, into the RAG pipeline.
- This is a simple enough approach, although it relies on the LLM summary being comprehensive, and ultimately its main weakness is that some information will always be missing - the summary will never be as good as the complete (raw) table.
- A better approach is to store the table as a separate type of object, along with the summary. Then at query time, if the summary indicates that this table is relevant to the query, present the LLM with the full raw table, so that it can access any required cells in the table and use it to respond to user queries.

### Managing Document Updates and Refresh

- includes both integrating new documents that have been added since the initial ingestion or the last update, but also updating existing documents that now have a newer version.
- importance of near real-time data availability cannot be overstated for numerous applications.
- News aggregation and threat intelligence analysis are two other example use-cases where rapid incorporation of new data is a core requirement.
- To address this you first need to implement *incremental updates* as a key part of your ingest pipeline. Instead of re-indexing the entire dataset every time a change occurs, incremental updates involve identifying only the modified documents (new, updated, or deleted) and updating the RAG pipeline accordingly.
- Your ingest pipeline needs to detect changes in the source data, and trigger a “refresh” - this can be achieved through [Change Data Capture](https://en.wikipedia.org/wiki/Change_data_capture) (CDC)
